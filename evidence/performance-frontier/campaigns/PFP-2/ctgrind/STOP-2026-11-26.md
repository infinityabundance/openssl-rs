# STOP — PFP-2: a secret-dependent branch in the new P-256 engine (release)

**Status: STOP.** PFP-2 remains `EXPERIMENT`. **PFP-5 cannot start until this is
fixed.** No source was changed by this finding.

- Date: 2026-11-26
- Subject: recorded PFP-2 distribution DSO
  `467527ae6a61fb217facd6f50bd1187fc25ce2dea3817d0b37c71bdd0ada9bf8`
  (`court/tmp/pfp2-recheck/distribution/libcrypto.so.3`), built from the PFP-2
  engine worktree at head `2004ea243` and committed as `34754764f`
  (`git diff 34754764f HEAD -- src/ec src/bn` is empty).
- Recorded population: debug lib test binary
  `e5ef938ab3b76e285f790ccf7a0b9132360bc301993d63f846774f9ae89e3347`,
  the exact binary named in `ctgrind/testbin.sha256`.

## Verdict: (B)

The instrument reports secret-dependent flow **in the new engine** when the
engine is measured on the artefact that ships. This is the STOP condition.

The recorded `3,023 errors / 123 contexts` reproduces exactly (repeat 2; band
`3,013–3,047 / 121–136`), and in that debug population the engine contributes
**zero** origin contexts: the recorded number is a population artefact (option
A explains the number). It does **not** exonerate the engine: the equivalent
sign population on the release DSO puts 58 origin contexts in the engine, and
the release instruction is a real `jne` on a tainted borrow. A green debug reading is not
evidence about the release binary, and the release binary is what ships.

## Offending site

- Exact site: **`src/ec/p256.rs:690`**,
  `let (_, b) = t[2 * LIMBS].overflowing_sub(borrow);` in `mont_reduce_into`
  (function at `src/ec/p256.rs:657-704`). The source is branchless by intent;
  the branch is compiler-introduced in the release build (AGENTS §5.2:
  source-level intent is not constant-time behaviour after optimisation). A
  line-tables-only release build from HEAD `d2d93c7d1` (DSO `b55b6ea8…`,
  same PCs) reports `mont_reduce_into (p256.rs:690)`; see
  `repro-2026-11-26/dbgrel-min.out`.
- Instructions in the recorded DSO (`mont_reduce_into` @ `0x189bc0`, base
  `0x4852000`):
  - `mont_reduce_into+0x34D`: `test %rcx,%rcx ; jne 0x189ec0`
  - `mont_reduce_into+0x361`: `je 0x189ec0`
  `%rcx` is the borrow of `t[LIMBS+i] - (m[i] & subtract)`; it is derived from
  the secret projective coordinates.
- Path from secret to branch:
  ECDSA nonce (secret) → `ecdsa_sign_setup` → `EC_POINT_mul` →
  `ossl_ec_scalar_mul_ladder` (`mult.rs:566`) → `p256_ladder_run::<Mont>`
  (`mult.rs:685`) → `P256Ladder::step` (`p256.rs:1523`) → `Mont::mul`
  (`p256.rs:755`) → `mont_mul` (`p256.rs:733`) → `mont_reduce_into`
  (`p256.rs:690`) → borrow → `jne`/`je`.
  The stack is in `repro-2026-11-26/s-sign-mont-1.out`; the disassembly is in
  `repro-2026-11-26/disassembly-mont_reduce_into.txt`.
- Same-engine extent: 58 origin contexts in the minimal MONT population
  (48 of them `mont_reduce_into`, plus `double_assign`, `add_assign`,
  `p256_ladder_run`). This is not one isolated instruction.

## Controls

- **Minimal MONT population** (one `EC_POINT_mul`, secret scalar limb values,
  no assertions, no test-only branches, no generic field kernel):
  **12,371 errors / 203 contexts**, of which **58 originate in the engine**.
- **Same population, generic (pre-engine) kernel**: **794 / 29**, **0 engine
  origins**. MONT is materially worse (15.6× errors, 7× contexts): the count is
  specific to the new engine.
- **Sign population on the release DSO**: MONT `12,494 / 250` (repeat
  `12,515 / 259`); generic `847 / 82`.
- **Population negative controls**: the same programs with defined scalars give
  `0 / 0` on both DSOs, so the harness itself introduces no undefined reads.
- **Profile dependence**: the same function in the debug test binary
  (`0x13c2780`, size `0xacb`) has no conditional jump on the borrow, and the
  debug sign run has zero `mont_reduce_into` contexts. The leak is in the
  release codegen.

## PFP-1 comparability

PFP-1's command is recorded in its log: the **same test, same debug lib test
binary profile**, `97217 errors / 186 contexts` (baseline `~97,200 / 190`).
The population class is the same, so the two are comparable as populations —
but the comparison that matters is contexts, not the error count: the engine
removes the per-bit generic `ec::field` reductions (38 PFP-1 contexts), so
186 → 123 is a subset plus line-shifted sites, and 97,217 → 3,023 is loop
multiplicity. Comparing `3,023 errors` to `186 contexts` is a category error.
**Neither PFP-1 nor PFP-2 measured the release engine**, so neither reading
can support a constant-time claim.

## Status consequences

- PFP-2 stays `EXPERIMENT`; no constant-time claim is made for the engine.
- PFP-5 is gated on removing the release branch at
  `src/ec/p256.rs:683-701` (and dispositioning the write-back `normalise`
  obligation).
- The `3,023 / 123` record in `ctgrind/summary.json` and its logs are retained
  unchanged as history. This note supersedes its use as a green reading, not
  its existence.
