## 2. STEP 1 — what the shipped `gf_mul` actually emits

`raw/gf_mul-before-adjudication.txt`, `raw/audit-before.disasm.txt`.

`gf_mul` is `pub(crate)` and is **inlined** in the pre-change DSO (no out-of-line
symbol). In `CRYPTO_gcm128_aad` (also `finish`, `setiv`, `crypt`) the complete
per-block multiply is:

```
2224ed: mov    ecx,0x7f                 ; loop counter: 128 iterations
2224fa: movabs r15,0xe100000000000000   ; the reduction constant R
22251f: test   cl,0x40                  ; bit of the public loop index
222522: cmovne rbp,r13                  ; operand-dependent select  -> cmov
222526: cmovne r13,rbx
22252a: and    rbp,r9                   ; mask, not branch
22252d: and    r13,r10
222536: cmove  rbp,rbx
22253d: cmove  r13,rbx
222558: test   r11b,0x1                 ; lsb of the running value
22255c: cmovne r8,r13                   ; v = lsb ? (v>>1)^R : v>>1 -> cmov
222563: add    ecx,0xffffffff
222566: jb     222510                   ; the only branch: fixed-count back-edge
```

Adjudication, by instruction rather than by source shape:

* the **operand-dependent** conditional (`(x >> (127-i)) & 1`) lowers to
  `test cl,0x40` + `cmovne` + `and`/`or` masks — **cmov/mask**, not a branch;
* the **`lsb`** conditional lowers to `test r11b,0x1` + `cmovne` — **cmov**, not a
  branch;
* the only conditional transfer in the loop is `add ecx,-1; jb`, whose flags come
  from the loop counter (`ecx` starts at `0x7f`), i.e. a **fixed 128-step loop**;
* there is **no secret-indexed memory operand** in the loop.

So the claim "`gf_mul` branches on `if lsb == 1`" is **not true of this digest**;
the source shape was lowered to conditional moves. This is an observation about
instructions, not a constant-time proof (see §8). The fast path introduced in
this batch replaces the loop entirely (§4).

## 3. AES-NI (all three key sizes)

`src/aes.rs`. Key expansion and both block directions are implemented with AES-NI
behind one production detection site.

* `ia32cap_aes_cleared` / `aes_ni_available` (`B-AES-DETECT`): safe Rust; the one
  production `is_x86_feature_detected!("aes")` call, cached in a `OnceLock`. The
  `OPENSSL_ia32cap` first-vector `~` clear mask (bit 25) forces the portable arm.
* `ni_subword_pair` + `aes_expand_ni` (`B-AES-EXPAND`): `SubWord`/`RotWord` come
  from `aeskeygenassist`; the recurrence is the authority's, so the logical key
  schedule is byte-identical to the portable transcription (verified by
  `aes_ni_matches_portable` over 64 random keys per size). No S-box table is read.
* `aes_encrypt_ni` (`B-AES-ENC`), `aes_decrypt_ni` (`B-AES-DEC`): the round count
  comes from the schedule, so 128/192/256 share the carrier; round keys are loaded
  at `rd_key + 4*round` (a public index).
* The dispatchers `aes_expand`, `AES_encrypt`, `AES_decrypt` each make one
  feature-guarded call; `AES_set_encrypt_key` / `AES_set_decrypt_key` keep their
  authority signatures and the existing `bswap_schedule`/inverse-mix transform.

`AesKey` layout, `#[repr(C)]`, and every exported symbol are unchanged.

## 4. PCLMULQDQ GHASH and the reduction bound

`src/modes/gcm.rs`.

* `ia32cap_pclmul_cleared` / `pclmul_available` (`B-GHASH-DETECT`): safe Rust; the
  one production `is_x86_feature_detected!("pclmulqdq")` call, `OnceLock`-cached;
  the `OPENSSL_ia32cap` first-vector clear mask (bit 1) forces the portable arm.
* `gf_mul_clmul` (`B-GHASH-MUL`): four `pclmul*` products assembled with XOR
  (carry-less) addition into a 256-bit polynomial, then `reduce_gcm`.
* `gf_mul` dispatches to it; `gf_mul_portable` keeps the bit-by-bit fallback and
  `R` is unchanged.

**Bit order.** GCM puts the coefficient of `x^0` in the most significant bit of
the big-endian value. The polynomial integers are therefore the 128-bit bit
reversal of the `u128` operands: `a = x.reverse_bits()`, `b = y.reverse_bits()`,
carry-less multiply, reduce, `result.reverse_bits()`. `reverse_bits` is a fixed
SWAR sequence (the audit shows only `lea`-style arithmetic, no memory operand).

**Reduction bound (fixed step count).** For modulus `M = x^128 + x^7 + x^2 + x + 1`,
`x^128 ≡ q(x) = x^7 + x^2 + x + 1`. A degree-≤254 product is `P = hi·x^128 + lo`
with `deg hi ≤ 126`.

1. First fold: `P ≡ lo + hi·q`. `deg(hi·q) ≤ 126+7 = 133`, so write
   `hi·q = c·x^128 + a` with `deg c ≤ 5` (at most 7 bits) and `deg a < 128`.
2. Second fold: `c·q` has `deg ≤ 5+7 = 12 < 128`, so there is no third fold.

The implementation is exactly three right-shifts to collect `c`, four left-shift/
XOR terms for `a`, then four left-shift/XOR terms for `c·q`: a constant number of
arithmetic operations, **no loop, no branch, no data-dependent count**. The
portable `gf_mul` remains the bit-by-bit 128-iteration fallback.

## 5. Unsafe surface, with boundary IDs

All new unsafe work is inside 128-bit intrinsic carriers. `unsafe_op_in_unsafe_fn`,
`undocumented_unsafe_blocks` and `missing_safety_doc` are deny-level and clean
(`cargo clippy --all-targets -D warnings` is green), so every unsafe block carries
a `SAFETY:` contract and every `unsafe fn` a `# Safety`.

| boundary | items | precondition established by |
|---|---|---|
| `B-AES-DETECT` | `ia32cap_aes_cleared`, `aes_ni_available` (safe) | CPUID via `is_x86_feature_detected!`, cached |
| `B-AES-EXPAND` | `ni_subword_pair`, `aes_expand_ni` (`#[target_feature(enable="aes")] unsafe fn`) | `aes_expand` checks `aes_ni_available()`; `user_key`/`key` extents from the C contract |
| `B-AES-ENC` | `aes_encrypt_ni` (`#[target_feature(enable="aes")] unsafe fn`) | `AES_encrypt` checks `aes_ni_available()`; `in`/`out` 16 bytes, live schedule |
| `B-AES-DEC` | `aes_decrypt_ni` (`#[target_feature(enable="aes")] unsafe fn`) | as `B-AES-ENC`, with a live decryption schedule |
| `B-GHASH-DETECT` | `ia32cap_pclmul_cleared`, `pclmul_available` (safe) | CPUID via `is_x86_feature_detected!`, cached |
| `B-GHASH-MUL` | `gf_mul_clmul` (`#[target_feature(enable="pclmulqdq")] unsafe fn`), `reduce_gcm` (safe, no unsafe) | `gf_mul` checks `pclmul_available()`; operands by value |

Per fast carrier: one `unsafe {}` block each (five total) plus one guarded call at
each dispatcher (`aes_expand`, `AES_encrypt`, `AES_decrypt`, `gf_mul`). The SIMD
loads/stores touch only the caller's 16-byte blocks and the schedule words at
public indices; `gf_mul_clmul` touches only locals. No new `#[no_mangle]`, no
`#[repr(C)]`/layout change, no `asm!`.

Mechanism accounting: **eliminated** on the fast path — S-box table indexing in
the AES state and key expansion, and the 128-iteration GHASH loop; **relocated** —
the SIMD/provenance obligations into the six boundaries above with one detection
predicate per extension; **hidden** — none found in the new carriers.

## 6. Correctness (before timing)

* `aes_ni_matches_portable`: 64 random keys per size (128/192/256): identical
  logical schedules, identical encrypt blocks, identical decrypt blocks, and the
  decrypt round-trip recovers the plaintext.
* `clmul_matches_portable_gf_mul`: 512 random pairs + 36 edge pairs (0, 1, all-ones,
  `R`, `1<<127`, `1<<64`) + `E(K,0)`-shaped hash keys, both as the key and as the
  operand: `gf_mul_clmul == gf_mul_portable` and `gf_mul == gf_mul_portable`.
* `gcm_rejects_tampered_ciphertext_aad_and_tag`: the unmodified quadruple is
  accepted; a one-bit flip in ciphertext, in AAD, or in tag is rejected.
* FIPS-197 C.1/C.2/C.3 (128/192/256, encrypt and decrypt) — existing test, now
  exercising the AES-NI dispatcher.
* NIST GCM test cases 1, 2 and 5 — existing tests, now on the CLMUL fast path.

Cross-library (`raw/diff-*.json`, `raw/diff-*.txt`): four operations
(`aes128gcm-64`, `aes128gcm-16k`, `aes256gcm-64`, `aes256gcm-16k`) and the 16-case
KAT set are **IDENTICAL** to the pinned OpenSSL 3.6.4 for **every** arm: `before`,
`after`, `off` (both bits cleared), `off-aes`, `off-pclmul`. `mismatches=0`.

## 8. Instruction audit of the new carriers (and its scope)

`raw/audit-after.json`, `raw/audit-after.disasm.txt`.

| carrier | insns | jcc | setcc | cmov | memory operands with an index register | SIMD op |
|---|---:|---:|---:|---:|---:|---|
| `aes_encrypt_ni` | 54 | 6 | 0 | 0 | 2 (input block; round key at public round) | `aesenc`,`aesenclast` |
| `aes_decrypt_ni` | 54 | 6 | 0 | 0 | 2 (input block; round key at public round) | `aesdec`,`aesdeclast` |
| `aes_expand_ni` | 634 | 8 | 1 | 1 | 0 | `aeskeygenassist` |
| `gf_mul_clmul` | 164 | **0** | **0** | **0** | **0** | four `pclmul*` |

Every `jcc` in the AES carriers is on a public quantity: null checks, the key-size
selector (`cmp esi,0x80/0xc0/0x100`) or the round/loop counter. Every `setcc`/`cmov`
is the round-count selector from the key size. The `gf_mul` dispatcher has four
`jcc` on the `OnceLock`/cached feature state and, in its inlined portable fallback
only, the cmov loop of §2. The wrappers `crypt`, `CRYPTO_gcm128_aad`, `_finish`,
`_setiv` contain length/buffer branches on public metadata and an inlined copy of
the portable GHASH fallback (`test cl,0x40` / `test dl,0x1` cmovs) that is skipped
when `pclmul_available()` is true; they also contain the call to `gf_mul_clmul`.

**Result.** The executed fast path has **no table indexing at all** (no
secret-indexed memory operand, no secret-derived branch and no secret-derived
address). The only AES memory operands are the input block and the round key at a
public round index.

**Scope.** This is an instruction-level classification at one digest
(`c772f71e…`, rustc 1.98.1, i9-13900K), not a constant-time proof. Absence of a
branch is not absence of a cache or latency leak: the data-dependent latency of
`pclmul`/`aesenc` is not measured here, and no other micro-architectural channel is
claimed. The portable fallback still runs the table/bit paths and is outside this
claim.

## 9. What this batch does NOT claim

* The **portable table AES is not constant-time**: `AES_SBOX`/`AES_INV_SBOX` are
  still indexed by secret state in `sub_bytes`, `inv_sub_bytes` and
  `aes_expand_portable`. **The STOP is open**, carried by PFP-63's portable half.
* The **portable GHASH fallback is not claimed constant-time**; its two source
  conditionals are cmov at this digest (§2), which is an observation, not a proof.
* The fast path is not claimed "constant-time" in the strong sense; the claim is
  exactly "no secret-indexed memory access, no secret-derived branch, no
  secret-derived address at the instruction level".
* No `SAFETY_DISCHARGED`/`SAFE_COMPATIBLE` promotion, and no closure of PFP-63.
* VAES/VPCLMULQDQ are **not used**; only AES-NI and PCLMULQDQ. Their availability
  is reported and positive-controlled, nothing more.
* The candidate is still 2.5× (64 B) and ~12–13× (16 KiB) the authority; no parity
  claim.
* The audit is bound to this DSO digest and this toolchain; a different compiler or
  CPU may lower the same source differently.
