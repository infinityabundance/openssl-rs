## 5. Residual register

- **R1 — Raw owning members and destructive reassignment.** `CmsEncryptedContentInfo.key/keylen`, `CmsKekRecipientInfo.key/keylen`, `CmsKeyTransRecipientInfo.encrypted_key/pkey/recip/pctx`, and `CmsAuthEnvelopedData.mac` are raw owning members. `CMS_RecipientInfo_set0_key` overwrites `kekri.key` without releasing the previous key (leak) and stores a caller buffer that `cms_ri_cb` will `OPENSSL_clear_free`. `CMS_RecipientInfo_set0_pkey` frees the previous `pkey` and stores the caller pointer without an up-ref.
- **R2 — Secret cleansing.** The content key (`ec.key`) is cleansed by `cms_env_clear_ec` and the `cms_ec_cb` ASN.1 `FREE_POST` hook; the KEK key is cleansed by `cms_ri_cb`; `cms_RecipientInfo_kekri_decrypt` allocates `ukey` with `OwnedBuf::new_cleansed_released`. `cms_RecipientInfo_ktri_decrypt` adopts a plain helper block and transfers it to the secret member in the same frame. `CMS_add0_recipient_key` and `CMS_RecipientInfo_set0_key` transfer caller secret buffers whose provenance and exclusivity are not stated; a caller-side alias can outlive the transfer.
- **R3 — Caller-asserted lengths and unchecked arithmetic.** `CMS_RecipientInfo_kekri_id_cmp` builds `length: idlen as c_int` with no `INT_MAX` check. `CMS_RecipientInfo_set0_key` accepts arbitrary `keylen`. `CMS_add0_recipient_key` bounds `idlen` but relies on the caller for `key`/`id` readable extents. `cms_RecipientInfo_kekri_encrypt` computes `(*ec).keylen + 8` without `checked_add`, and passes `(*ec).keylen as c_int` to `EVP_EncryptUpdate`.
- **R4 — Structural validity of caller-supplied objects.** The `# Safety` clauses say “live”, not “structurally valid for the selected arm”. Required members (`content_type`, `d`, `encrypted_key`, `kekid`, `key_identifier`, `mac`, `recipient_infos`, stack elements) are dereferenced without tag/null checks. `type_`/`content_type` select a union arm but do not establish that `d` matches the arm.
- **R5 — Partial initialisation and failure cleanup.** `cms_enveloped_data_init`/`cms_auth_enveloped_data_init` install `cms.d` before the allocation NULL check. `cms_RecipientInfo_ktri_init` installs `ri.d` before its NULL check and returns a partially built RI to the caller on later failures. `CMS_add0_recipient_key` pushes `ri` before installing the adopted fields and ignores the `X509_ALGOR_set0` result. The create paths free only the container on failure.
- **R6 — Copy/dup aliasing.** `CMS_EnvelopedData_decrypt` temporarily aliases the borrowed `env` in a stack `CMS_ContentInfo`, assigns a static `OBJ_nid2obj` to `content_type`, and must null `d`/`content_type` before freeing the temporary. `CMS_RecipientInfo_kekri_id_cmp` aliases caller `id` in a stack `Asn1String`. `cms_RecipientInfo_ktri_init` up-refs `recip`/`pk`; `CMS_add1_recipient` borrows `recip`. `CMS_add0_recipient_key` adopts `date`/`other_type_id`/`other_type` without a dup.
- **R7 — Callback re-entrancy and provider dispatch.** `ossl_cms_env_asn1_ctrl` dispatches to the KEM/DH/EC/RSA handlers while holding raw `ri`/`pkey`. `ossl_cms_RecipientInfo_wrap_init` invokes a legacy cipher ctrl callback with a NULL `EVP_CIPHER_CTX` and dereferences the callback-returned `kk` cipher. The BIO init/final paths pass borrowed unprotected-attribute stacks through `EVP_CIPHER_CTX_ctrl`. `ossl_cms_pkey_get_ri_type` runs provider `encrypt_init`/`derive_init`/`encapsulate_init`. No lock, rollback, or poisoned-state contract is stated.
- **R8 — Stack/RecipientInfo ownership and element typing.** Stacks own `CMS_RecipientInfo` objects; `CMS_get0_RecipientInfos` returns a borrowed stack. `OPENSSL_sk_value` results are cast by `type_` in `ossl_cms_RecipientInfos_set_cmsctx`, `cms_env_set_version`, `cms_env_set_originfo_version`, and `cms_env_encrypt_content_key`; element non-null/type is caller-asserted.
- **R9 — Unchecked arithmetic/allocation.** `OwnedBuf::new`/`new_cleansed_released` report allocation failure, but `ec.keylen + 8` is unchecked and several `usize`/`c_int` length conversions are unchecked (R3).
- **R10 — Borrowed-return aliasing.** `CMS_get0_RecipientInfos`, `CMS_RecipientInfo_get0_pkey_ctx`, `ktri_get0_algs`, `ktri_get0_signer_id`, and `kekri_get0_id` return interior pointers borrowed from `cms`/`ri`; lifetime and alias exclusivity are C-caller obligations.
- **R11 — Static content-type and borrowed ownership.** `cms_enveloped_data_init`/`cms_auth_enveloped_data_init` free the old `content_type` and install static `OBJ_nid2obj` objects; `CMS_EnvelopedData_decrypt` does the same for its temporary container and must null before free.
- **R12 — Cipher provenance.** `cms_get_key_wrap_cipher` returns a fetched cipher; `ktri_decrypt` mixes fetched and legacy (`EVP_get_cipherbyname`) ciphers; `wrap_init` obtains `kk` from a callback and then fetches by its name. Lifetime/ownership of each pointer is not uniform.

## 7. Highest-risk groups

1. **D074/D075 — `CMS_RecipientInfo_set0_key` (`cms_env.c:843-856`; census 1578, 1584–1593; HEAD 1579, 1585–1594).** `UNATTRIBUTED`. The function stores the caller's `key` as the owning `kekri.key` member, which `cms_ri_cb` later releases with `OPENSSL_clear_free((*kekri).key, (*kekri).keylen)`. The `# Safety` clause says only “readable for `keylen`”, so allocator provenance, exclusive ownership, cleansing, and the fact that the previous key is not released are all hidden obligations. A caller that keeps its buffer, frees it, or passes non-seam memory causes a double-free or invalid free.
2. **D059/D060 — `CMS_RecipientInfo_set0_pkey` (census 1014, 1019–1035; HEAD 1015, 1020–1036).** `UNATTRIBUTED`. The function frees the existing `ktri.pkey` and stores the caller pointer without an up-ref. The stated precondition (“`pkey` is NULL or live”) omits the ownership transfer and the requirement that the caller not free or alias the key. A caller that also frees it causes a double-free; a caller that keeps using it races the ASN.1 free.
3. **D069–D071 — `CMS_add0_recipient_key` (census 1365, 1378–1500, 1471; HEAD 1366, 1379–1501, 1472).** `CONTRACTED` but high risk. The C-side contract says “the buffers are the caller's and adopted” but does not state provenance, extent, exclusivity, or the release path (`key` is cleansed by `cms_ri_cb`; `id`/`date`/`other` are ASN.1-owned). The function pushes the `ri` before installing the adopted fields and ignores the `X509_ALGOR_set0` return, so a late failure leaves a stack-visible partially initialised recipient.
4. **D064–D066 — `cms_RecipientInfo_ktri_decrypt` (census 1145–1308; HEAD 1146–1309).** `CONTRACTED` but security-sensitive. A plain `OwnedBuf::adopt_plain_nullable` result becomes the secret content key; the previous `ec.key` is cleansed with `OPENSSL_clear_free`, and the new block is installed with `into_raw`. The correctness of the cleanse depends on the caller-supplied `ec`/`ktri` being structurally valid and on the same `keylen` being used for release.
5. **D125–D127 — `ossl_cms_RecipientInfo_wrap_init` (census 2605–2761; HEAD 2606–2762).** `CONTRACTED` but callback-heavy. The legacy cipher ctrl is invoked with a NULL `EVP_CIPHER_CTX` and a stack out-slot; the returned `kk` is dereferenced and its name is fetched. The contract states only that `ri`/`cipher` are live. Reentrancy, callback failure, and an arbitrary `kk` are not covered.
