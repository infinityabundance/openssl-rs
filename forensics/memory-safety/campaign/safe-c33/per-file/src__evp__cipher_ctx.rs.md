## 4. Residual obligation register

These obligations remain after the current contracts. They are not repaired by a SAFETY comment.

1. **`block_size` is not bounded before `ctx->buf`/`ctx->final_` indexing.** `evp_EncryptDecryptUpdate` uses `cipher->block_size` for the `ctx->buf` copies and `ctx->buf_len` arithmetic; `EVP_EncryptFinal_ex` writes padding bytes at `ctx->buf[buf_len..block_size]`; `EVP_DecryptUpdate` copies a whole `cipher->block_size` block into `ctx->final_`; `EVP_DecryptFinal_ex` reads `ctx->final_[block_size-1]` and walks the padding. Nothing checks `block_size <= EVP_MAX_BLOCK_LENGTH` (32), and the source comment only cites the authority's non-fatal `ossl_assert`. A malformed legacy method or a provider that reports a larger block size therefore produces an out-of-bounds access in a function whose `# Safety` only says the context is armed. `EVP_CIPHER_CTX_get_block_size` returns the same unchecked value.
2. **`EVP_CIPHER_CTX_set_cipher_data` installs an unconstrained owning pointer.** The setter stores the caller's `void *` in `ctx->cipher_data`; `EVP_CIPHER_CTX_reset` later cleanses and `CRYPTO_free`s it at `cipher->ctx_size`, and the legacy copy path copies `ctx_size` bytes from it. The setter's contract does not require an allocator-seam block, a matching `ctx_size`, or exclusive ownership, so a C caller can install a stack/static pointer or a too-small block. This is a hidden obligation, not a documented boundary.
3. **`EVP_CIPHER_CTX_ctrl` has command-specific pointer/length preconditions that the code does not check.** `EVP_CTRL_AEAD_GET_TAG`/`SET_TAG`, `EVP_CTRL_AEAD_SET_IV_FIXED`, `EVP_CTRL_GCM_IV_GEN`, `EVP_CTRL_AEAD_SET_MAC_KEY`, `EVP_CTRL_RAND_KEY` and the RC2/RC5 commands pass `ptr_` with `sz = arg as usize`; a negative `arg` becomes a huge `usize` before the provider sees it. `EVP_CTRL_TLS1_1_MULTIBLOCK_ENCRYPT` dereferences `ptr_` as `MultiblockParam` without the `arg >= size_of::<MultiblockParam>()` check that the AAD command performs. The `# Safety` text says `ptr` must follow the command contract but does not state these per-command extents, and no code establishes them.
4. **`EVP_CIPHER_CTX_set_key_length` dereferences `(*c).cipher` without a NULL check.** A fresh or reset context (`cipher == NULL`) faults before the function can raise `EVP_R_NO_CIPHER_SET`; the `# Safety` only says `c` is live. The provider arm then reads `(*cipher).prov` and the legacy arm reads `(*cipher).flags`.
5. **`EVP_CIPHER_CTX_get_key_length` and `_get_iv_length` cast a `*const` away and write the cache.** The write-through-`*mut` is the authority's own, but neither the `# Safety` nor the caller set requires a genuinely mutable object. Passing a context in read-only storage (a static, or a caller's `const` view) is a write fault. The same functions also cache provider-controlled lengths with `as c_int`/`as usize` conversions that can truncate or wrap.
6. **Provider/application callback reentrancy.** `cleanup`, `freectx`, `newctx`, `einit`, `dinit`, `einit_skey`, `dinit_skey`, `p_einit`, `p_dinit`, `cupdate`, `cfinal`, `ccipher`, `do_cipher`, `ctrl`, `dupctx`, `set_ctx_params`, `get_ctx_params`, `settable_ctx_params`, `gettable_ctx_params`, `set_asn1_parameters`, `get_asn1_parameters`, `copyctx` and `init` are caller/provider-controlled. The code commonly reads or writes `ctx`, `cipher`, `algctx`, `fetched_cipher`, `cipher_data` or `flags` after the callback returns; a callback that frees or mutates the object is not guarded. The C ABI also allows an application allocator hook and an application `ctrl` callback to re-enter.
7. **Raw owning members and ownership reconstruction.** `EvpCipherCtx::cipher` (borrowed), `fetched_cipher` (owned method reference), `cipher_data` (owned legacy block at the dynamic `cipher->ctx_size`), `algctx` (provider-owned opaque context) and the borrowed `app_data` are raw fields. `EVP_CIPHER_CTX_reset`, `EVP_CIPHER_CTX_copy`, the two legacy init paths and `destroy_body` release or re-point them by hand. There is no owner slot or typed borrow that prevents a second release or a stale `cipher` after `fetched_cipher` is freed.
8. **Caller-asserted buffer extents and lengths.** `EVP_EncryptUpdate`/`EVP_DecryptUpdate` (`out` for `inl` plus a block, `in` for `inl`, `outl`), `EVP_EncryptFinal*`/`EVP_DecryptFinal*` (`out` for a block, `outl`), `EVP_Cipher` (`out`/`in` per the method), `EVP_CIPHER_CTX_rand_key` (`key` for the key length), `EVP_CIPHER_CTX_get_updated_iv`/`get_original_iv` (`buf` for `len`), the two pipeline init/update/final entries (`numpipes` arrays), `EVP_CipherInit_SKEY` (`iv` for `iv_len`), `pipeline_init` (`key` for `keylen`, `iv` as `numpipes` pointers), and every `OSSL_PARAM` array. No group checks these extents; `EVP_CIPHER_CTX_get_asn1_iv` is the one place a local length is bounded (16 bytes).
9. **Key/IV and secret-bearing buffers.** The init family forwards caller `key`/`iv` pointers to provider callbacks and to the legacy `init`; the provider may retain them, and the code records no copy or cleanse for them. `EVP_CIPHER_CTX_rand_key` writes a caller buffer with no failure cleanse. `EVP_CIPHER_CTX_reset` cleanses only the legacy `cipher_data` block; provider `algctx` release is delegated to `freectx` with no cleanse obligation. `EVP_CIPHER_CTX_ctrl`'s `SET_MAC_KEY` and tag commands pass secret/tag buffers through `ptr_`.
10. **Copy/dup aliasing and partial init.** `EVP_CIPHER_CTX_copy` uses `ptr::copy_nonoverlapping` for a whole struct and for `cipher_data`; `out == in` is caller error and the `# Safety` states distinctness but no code checks it. The provider arm calls `dupctx` after the struct copy and nulls `algctx`; a failing `dupctx` returns 0 with `out` already overwritten. `EVP_CIPHER_CTX_dup` frees the new context on that refusal. `pipeline_init` stores `numpipes` before arming; a failed arm leaves the field changed. `EVP_CIPHER_CTX_set_padding` and `EVP_CIPHER_CTX_set_flags`/`clear_flags` change context flags before notifying the provider.
11. **ASN.1/X509_ALGOR caller pointers and lengths.** `EVP_CIPHER_param_to_asn1`/`asn1_to_param`, their two shared bodies, `EVP_CIPHER_get_asn1_iv`/`set_asn1_iv`, and `EVP_CIPHER_CTX_get_algor_params`/`set_algor_params` dereference caller-supplied `ASN1_TYPE`/`X509_ALGOR` and, for the provider path, trust the implementation callbacks. `EVP_CIPHER_set_asn1_iv` passes `EVP_CIPHER_CTX_get_iv_length`'s answer (which can be `-1`) to `ASN1_TYPE_set_octetstring` as the length; only the original IV buffer is locally known to be 16 bytes. `EVP_CIPHER_CTX_get_algor_params` trusts the provider's `return_size` for the `OwnedBlock` allocation and the `d2i_ASN1_TYPE` length.
12. **Destructor implementer obligations and refcount lifetime.** `CtxDestroy::destroy_body` for `EvpCipherCtx` is invoked by a safe `Drop`; the contract that it releases each member exactly once, never the enclosing block, and is valid for the zeroed state is asserted by the impl, not checked by `OwnedCtx`. `EVP_CIPHER_CTX_free` assumes allocator provenance and no double-free. `EVP_CIPHER_CTX_get1_cipher` calls `EVP_CIPHER_up_ref`, which is a no-op for non-dynamic methods, so the returned pointer is not a real owned reference for a legacy/static method.
13. **Pre-existing RT-CIPHER compatibility residual: `defltwrap.pad21`.** `courts/phase8/rt_cipher_probe.c:2563-2577` drives `AES-128-WRAP-PAD` with 21 bytes; the authority returns a ciphertext digest and the candidate answers `EVP_EncryptUpdate == 0`. This is a compatibility residual, not a safety finding, and it is **not** introduced by the `cipher_ctx.rs` safety patch: rebuilding HEAD `a919d9dd4` with the patch removed reproduced the same single residual (`authority 6fc14133…`, `candidate 0`) over the same 7291 observations, and `RT-CIPHER-MEM` remained 382/382 with zero residuals. Witness: `build_phase2.sh` + `phase8_courts.court("RT-CIPHER", …)` on the unpatched tree, 2026-10-18. The patch neither introduces nor repairs it; the provider wrap-pad path needs a separate investigation.

## 7. What would make this audit `INDEPENDENTLY_CHECKED`

For each group, an independent reviewer would need: the exact source and build identity; a contract witness for each precondition (a caller, an ABI declaration, or an owner invariant); a runtime/static check that fires on a deliberate violation (Miri/tree-borrows, ASan/guard pages, custom allocator, callback-reentrancy harness, refcount/double-free negative control, or a malformed-cipher/`block_size` harness); and a written disposition of every residual. For the `UNATTRIBUTED` groups the first evidence is a corrected contract or a code check: the ctrl command extents, the `cipher_data` provenance/size rule, the `block_size <= EVP_MAX_BLOCK_LENGTH` bound, the setter's NULL-cipher guard, and the const-cast mutability rule. Absent those, the group remains `CONTRACTED` or `ESTABLISHED`, and the file remains not `SAFETY_DISCHARGED`.
