## 4. Residual obligation register

These obligations remain after the current contracts. They are not repaired by a `SAFETY:` comment.

1. **Raw owning members and union arms** — `EvpPkeyCtx::propquery` (owned `*mut c_char`), `keymgmt`/`op_kex_exchange`/`op_sig_signature`/`op_ciph_cipher`/`op_encap_kem` (owned method references), `pkey`/`peerkey` (owned key references), `rsa_pubexp` (owned `BIGNUM`), and the cached `dist_id`/`dist_id_name` pair. `destroy_body` frees them directly (`src/evp/pkey_ctx.rs:1006-1020`), `evp_pkey_ctx_free_cached_data` blind-frees the cached pair (`:870-871`), and `evp_pkey_ctx_free_old_ops` selects one union arm from `operation` (`:766-805`). There is no owner slot or typed borrow that enforces these relations.
2. **Provider/table callback reentrancy** — `gettable_ctx_params`, `settable_ctx_params`, `set_ctx_params`, `get_ctx_params`, `gen_set_params`, `gen_get_params`, all four `freectx` and all four `dupctx` function pointers, and every `fixup_args` table row are caller/provider-controlled. The code commonly reads context fields or the method after the callback returns; a callback that frees or mutates the object is not guarded. The translation loop's `cleanup_translation_ctx` and the per-call `XlatCtx` are stack-owned, but the provider may re-enter the context.
3. **Caller-asserted lengths and pointer types** — `EVP_PKEY_CTX_set1_*`/`add1_*` and `set_mac_key` (`data`/`datalen`), `EVP_PKEY_CTX_get_group_name` (`name`/`namelen`), `EVP_PKEY_CTX_set_signature` (`sig`/`siglen`), `EVP_PKEY_CTX_set1_id` (`id`/`len`), `EVP_PKEY_CTX_ctrl`/`ctrl_str` (`p1`/`p2`), every `OSSL_PARAM` array, and all `fix_*` `p1`/`p2` pairs. No group checks these extents; the table row is the only type evidence.
4. **Hidden obligations in exported signatures** — `EVP_PKEY_CTX_get_signature_md` documents `md` as NULL-or-writable but writes `*md` unconditionally at `:9550` (and through the legacy GET_MD fixer); `EVP_PKEY_CTX_get1_id_len` documents `id_len` as NULL-or-writable but `fix_distid_len` writes `*(size_t *)p2` at `:3565`; `EVP_PKEY_meth_copy` documents only live pointers but `ptr::copy_nonoverlapping` at `:2145` is UB for the legal C self-copy `dst == src`. These are not discharged by the comments.
5. **Refcount and partial-failure ownership in `EVP_PKEY_CTX_dup`** — the new context stores `op_kex_exchange`/`op_sig_signature`/`op_ciph_cipher`/`op_encap_kem` before calling `up_ref` (`:1101`, `:1131`, `:1158`, `:1186`). If `up_ref` returns 0, the refusal path drops `rctx`, whose `destroy_body` releases the stored method pointer even though the new context never took a reference. The provider `dupctx` is also trusted to return a new algctx rather than the source pointer.
6. **Unchecked arithmetic on provider-controlled sizes** — `evp_pkey_ctx_add1_octet_string` computes `os_params[0].return_size + datalen as usize` at `:9835` and `info_len + datalen` at `:9876` without `checked_add`; `return_size` is provider-controlled. `evp_pkey_ctx_store_cached_data` receives `p1 as usize` from `EVP_PKEY_CTX_ctrl` at `:10551`, so a negative ctrl length becomes a huge `usize` before `CRYPTO_memdup` at `:10802`.
7. **Global registry state and borrowed methods** — `APP_PKEY_METHODS` is a `static mut` accessed without a lock by `EVP_PKEY_meth_add0` (`:2190-2209`), `EVP_PKEY_meth_remove` (`:2272`) and `evp_app_cleanup_int` (`:2249-2254`). The registry stores borrowed `*const EvpPkeyMethod` values with no lifetime tie; `EVP_PKEY_meth_free` only frees `DYNAMIC` methods, so freeing or re-registering the same method is a caller error.
8. **Borrowed strings and algorithm pointers** — `EvpPkeyCtx::keytype` is copied by `EVP_PKEY_CTX_dup` (`:1072`) and read by `fix_group_ecx` (`:6902`); `get_cipher_name`/`get_md_name` return borrowed names that `fix_cipher_md` passes to `strlen` without a NULL check (`:3465`, `:3480`); `EVP_PKEY_CTX_get_signature_md` trusts the provider to NUL-terminate the 80-byte name buffer before `evp_get_digestbyname_ex` (`:9544`).
9. **Destructor implementer obligations** — `CtxDestroy::destroy_body` for `EvpPkeyCtx` and `EvpPkeyMethod` is invoked by a safe `Drop`. The contract that each body releases each member exactly once, never the enclosing block, and is valid for the zeroed state is asserted by the impl, not checked by `OwnedCtx`. `evp_pkey_ctx_free_old_ops` does not clear `op_keymgmt_genctx` after `gen_cleanup` (`:802-804`); callers currently reset `operation` to `UNDEFINED`, which is what keeps the destructor from a second `gen_cleanup`, but the field itself is left dangling.
10. **Type-erased translation state** — `XlatCtx::p1`/`p2` and `XlatEntry` are a C-style tagged union without a Rust tag: `default_fixup_args` casts `p2` to `BigNum` (`:4281`) or to `char *` (`:4318-4329`) according to the table row, and every `fix_*` function does the same. The table row, not the type system, is the only guarantee.

## 7. What would make this audit `INDEPENDENTLY_CHECKED`

For each group, an independent reviewer would need: the exact source and build identity; a contract witness for every precondition (a caller, an ABI declaration, a table row, or an owner invariant); a runtime/static check that fires on a deliberate violation (Miri/tree-borrows, ASan/guard pages, custom allocator, callback-reentrancy harness, refcount/double-free negative control); and a written disposition of every residual. For this file the minimum additional controls are a self-copy control for `EVP_PKEY_meth_copy`, NULL out-parameter controls for `get_signature_md` and `get1_id_len`, a failed-`up_ref` control for `EVP_PKEY_CTX_dup`, an overflowing provider `return_size` control for `add1_octet_string`, and a negative-length ctrl control for the cached-data path. Absent those, every group remains `CONTRACTED` or `ESTABLISHED`, and the file remains not `SAFETY_DISCHARGED`.
