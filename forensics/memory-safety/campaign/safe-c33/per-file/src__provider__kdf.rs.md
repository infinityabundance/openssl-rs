1. **R1 — raw owning members and self-asserted destructors.** Every KDF context is a `#[repr(C)]` block with raw owning members: `secret`/`info`/`salt`/`pass`/`key`/`xcghash`/`session_id`/`prefix`/`label`/`data`, fetched `EVP_MD`/`EVP_MAC`/`EVP_CIPHER` handles, `KdfScrypt::propq`/`sha256`, `KdfHmacDrbg::base.ctx`, and `KdfArgon2::memory`/`md`/`mac`/`propq`. The 14 `unsafe impl KdfDestroy` bodies (`src/provider/kdf.rs:474-651`) release them and are called from the safe `OwnedCtx::Drop` (`:401-409`); the trait is `unsafe` (`:344`), but its implementers are the only place the destructor and zero-validity obligations are stated.
2. **R2 — provider dispatch and reentrancy.** All 134 `unsafe extern "C"` callbacks are installed in the 21 `pub(crate)` dispatch tables: `SSKDF_FUNCTIONS`, `X963KDF_FUNCTIONS`, `X942KDF_FUNCTIONS`, `PKCS12KDF_FUNCTIONS`, `SSHKDF_FUNCTIONS`, `PBKDF2_FUNCTIONS`, `HKDF_FUNCTIONS`/`HKDF_SHA256_FUNCTIONS`/`HKDF_SHA384_FUNCTIONS`/`HKDF_SHA512_FUNCTIONS`, `TLS13_KDF_FUNCTIONS`, `TLS1_PRF_FUNCTIONS`, `KBKDF_FUNCTIONS`, `SCRYPT_FUNCTIONS`, `KRB5KDF_FUNCTIONS`, `HMACDRBG_KDF_FUNCTIONS`, `ARGON2I_FUNCTIONS`/`ARGON2D_FUNCTIONS`/`ARGON2ID_FUNCTIONS`, `PBKDF1_FUNCTIONS`, and `PVKKDF_FUNCTIONS`. `new`/`free`/`reset`/`dup`/`derive`/`set_ctx_params`/`get_ctx_params` can re-enter through `EVP_MAC_*`, `EVP_Digest*`, `EVP_CIPHER_*`, `EVP_MD_fetch`/`EVP_MAC_fetch`, the `CRYPTO_*` allocator hook, and provider dispatch. The code commonly re-reads `ctx` fields after such calls; a callback that frees or mutates the context is not guarded.
3. **R3 — caller-asserted lengths and pointer extents.** Every derive callback takes the caller's `key`/`out` pointer and `keylen`/`outlen`, and every core helper repeats that obligation in its `# Safety`. `OSSL_PARAM` arrays are walked until a NULL key; `data`/`data_size` pairs are trusted; context buffer lengths (`secret_len`, `salt_len`, `pass_len`, `key_len`, `info_len`, `prefix_len`, `label_len`, `data_len`) come from prior `OSSL_PARAM` copies. Some helpers add a ceiling (`SSKDF_MAX_INLEN`, `X942KDF_MAX_INLEN`, HKDF `n <= 255`), but the actual destination extent is never checked at the C ABI.
4. **R4 — KDF output buffers.** `sskdf_hash_kdm`/`sskdf_mac_kdm` (`:841`, `:1019`), `x942kdf_hash_kdm` (`:2157`), `sshkdf` (`:3343`), `pbkdf2_derive` (`:3903`), `pkcs12kdf_derive` (`:2830`), `hkdf_expand` (`:4692`), `tls1_prf_p_hash`/`tls1_prf_alg` (`:6022`, `:6119`), `kbkdf_derive_inner` (`:6757`), `scrypt_alg` (`:7605`), `krb5kdf_alg` (`:8394`), `blake2b*` (`:10507-10627`), and `kdf_pbkdf1_do_derive` (`:11978`) write exactly the caller-supplied length. The material exception is **`krb5kdf_alg`**: after deriving `okey_len` bytes it calls `krb5kdf_fixup_des3_key(okey)` (`:8502-8503`) for a 3DES cipher, and that helper writes 24 bytes (`:8242-8257`) even when `okey_len < 24`; the `key_len != okey_len` guard does not reject equal-but-short lengths. The same shape exists in `openssl-3.6.4-production/providers/implementations/kdfs/krb5kdf.c:616`, so this is a recorded compatibility residual, not a transcription slip.
5. **R5 — partial initialisation and failure cleanup.** `OwnedCtx` zero-allocates every context and adopts it from the same allocation, so a failed `new` cannot produce a partially constructed owner. `dup` paths build a fresh zeroed context and free it through the full destructor on failure. The exception is **Argon2**: `argon2_initialize` allocates `ctx.memory` (`:10403-10409`), but only `argon2_finalize` releases it (`:10480-10496`). If `fill_memory_blocks` fails (`:10972`) or `argon2_initialize` fails after the matrix allocation, `kdf_argon2_derive` returns 0 with `ctx.memory` still live; neither `kdf_argon2_reset` (`:10986-11022`) nor the `KdfDestroy` body (`:601-638`) releases it. The authority has the same leak (`argon2.c:986-1015`, `:1120-1150`).
6. **R6 — secret cleanse and lifetime.** `CRYPTO_clear_free` is used for most secret buffers, and the stack bounce buffers are cleansed at their single exits. Two concrete under-cleanses remain. (a) `sskdf_mac_kdm_cleanup` releases `kmac_buffer` with the caller's `kmac_out_len` (`:1164`); when the caller left the KMAC width unspecified, `kmac_init` redefines its own local to `derived_key_len` and allocates that many bytes (`:998-1003`), so cleanup passes 0 and does not cleanse the buffer. The early failure path already uses `derived_key_len` (`:1063`) — an improvement over the authority — but the normal exit does not. (b) `pbkdf1_derive_skey` allocates the derived key with `CRYPTO_zalloc` and `OwnedBuf { clear: false }` (`:12388-12394`), so `Drop` is a plain `CRYPTO_free`; the key bytes are left in freed storage. `pkcs12kdf_derive` likewise frees the password/salt expansion buffer `i_buf` with plain `CRYPTO_free` (`:2939`). Both match the authority (`pbkdf1.c:460-474`, `pkcs12kdf.c:133-137`) and are recorded, not endorsed. Several struct clears use `ptr::write_bytes` (`sskdf_reset :1209`, `x942kdf_reset :2322`, `pkcs12kdf_cleanup :2973`, `sshkdf_reset :3473`, `pbkdf2_cleanup :4078`, `hkdf_reset_ex :5051`, `tls1_prf_reset :6210`, `kbkdf_reset :6919`, `krb5kdf_reset :8555`, `kdf_argon2_init :10748`/`reset :11021`, `pbkdf1_cleanup :12058`), matching the authority's `memset`; they are not volatile cleanses and may be elided. Only `hmac_drbg_kdf_reset` (`:8967`) and `pvk_cleanup` (`:12538`) use the crate's volatile `cleanse`.
7. **R7 — duplicate/copy aliasing and refcounts.** Duplicates use `ossl_prov_memdup`/typed copies rather than whole-struct shallow copies, so no self-copy aliasing was found. Two failure-path defects remain. (a) `kdf_scrypt_dup` takes `EVP_MD_up_ref(src->sha256)` at `:7834` but assigns `dest.sha256` only at the end (`:7865`); if the `propq` duplication (`:7839`) or either `memdup` (`:7845`, `:7851`) fails, `kdf_scrypt_free(dest)` sees `dest.sha256 == NULL` and the extra reference leaks. (b) `kbkdf_dup` calls `EVP_MAC_CTX_dup(src->ctx_init)` unconditionally (`:6948`); a context duplicated before a MAC is set dereferences NULL. Both mirror `scrypt.c:105-127` and `kbkdf.c:161-190`. `hmac_drbg_kdf_base_dup` raw-copies the fixed `k`/`v` arrays (`:9003-9004`) but only after a successful digest copy, and the destination is a fresh zeroed context.
8. **R8 — Argon2 matrix and thread state.** `fill_mem_blocks_mt` stores the raw `ctx` in each `Argon2ThreadData`, starts worker threads through `ossl_crypto_thread_start`, and joins/cleans handles in the authority's order (`:10138-10248`). The spawn-failure arm joins from index 0, including slots the recycle step has already joined (`:10207-10218`), and the derive enforces `threads <= lanes` only when `threads > 1` (`:10937-10946`). The matrix is secret for `ARGON2_I`/`ARGON2_ID` and is released with `CRYPTO_secure_clear_free`/`CRYPTO_clear_free` in `finalize`; the failure-path leak is R5.
9. **R9 — ownership adoption and transfer provenance.** `OwnedCtx::new` (`:366-375`), `into_raw` (`:383-387`), `from_raw` (`:393-396`), and `OwnedBuf::take` (`:433-447`) are the adoption seams. Each call site asserts provenance, full extent, alignment, exclusive ownership, and the exact release (plain vs clear). `destroy_body` implementers are the only statement of the zero-validity half.
10. **R10 — fallible arithmetic.** `pkcs12kdf_derive` computes `v * saltlen.div_ceil(v)`, `v * passlen.div_ceil(v)`, and `slen + plen` without `checked_mul`/`checked_add` (`:2867-2874`); an overflow can under-size `i_buf` and the copy loops then index past it. `scrypt_alg` uses a mix of wrapping/checked expressions and a `usize`/`c_int` cast on `blen` (`:7605-7700`). `pbkdf2_derive`/`pbkdf2_lower_bound_check_passed` use `wrapping_mul` deliberately to reproduce the authority's overflow behaviour (`:3852`, `:3923`).

## 7. What would make this audit `INDEPENDENTLY_CHECKED`

For each group, an independent reviewer would need: the exact source and build identity; a contract witness for every precondition (the dispatch table row, an owner invariant, or an exported ABI declaration); a runtime/static check that fires on a deliberate violation (Miri/tree-borrows, ASan/guard pages, allocator witness, callback-reentrancy harness, refcount/double-free negative control); and a written disposition of every residual. The minimum additional controls for this file are: a live/NULL/double-free court for the 14 `KdfDestroy` bodies; a guard-page output-extent court for `krb5kdf_alg` with a 3DES cipher and `okey_len < 24`; refcount/failure-injection controls for `kdf_scrypt_dup`; a dup-before-MAC NULL control for `kbkdf_dup`; failure-injection and LSan controls for the Argon2 matrix path; a cleanse-length instrument for the defaulted KMAC width and for `pbkdf1_derive_skey`/`pkcs12kdf_derive`; and arithmetic-overflow controls for `pkcs12kdf_derive`. Absent those, every group remains `CONTRACTED` or `ESTABLISHED`, and the file remains not `SAFETY_DISCHARGED`.
