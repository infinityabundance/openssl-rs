## 4. Residual register

### R1 — Secret-bearing buffers and cleansing

| # | Residual obligation, with the concrete site |
|---|---|
| R1.1 | `destroy_ctx_body` (1166–1195) classifies members by release: `psk`, `key`, `nonce`, `exportersec`, `shared_secret`, `ikme` are SECRET_DATA and use `CRYPTO_clear_free`; `propq`, `pskid`, `authpub` are PUBLIC_DATA and use `CRYPTO_free`; `authpriv` is SECRET_DATA released by `EVP_PKEY_free`. This classification is correct, but it is still a hand-maintained list: adding a member without adding its release is silent. |
| R1.2 | `hpke_do_middle` (2024–2025) holds the HKDF extract output in a 512-byte stack `secret` and **never cleanses it**, on success or on any failure arm. | R1.3 | `hpke_decap` success stores `(*ctx).shared_secretlen = lsslen` (1985) although the allocation extent is `alloc_len` (1969). `destroy_ctx_body` cleanses only `shared_secretlen` (1186–1191), so if `EVP_PKEY_decapsulate` writes back a shorter length, the tail of the KEM secret survives in the freed block. | R1.4 | `hpke_encap` passes `&mut (*ctx).shared_secretlen` to the second `EVP_PKEY_encapsulate` (1826–1827), so the stored length may be smaller than the allocated `lsslen` (1811). `destroy_ctx_body` then cleanses only the stored length. |
| R1.5 | `hpke_aead_dec` failure (1405–1406) cleanses the caller's `pt` for `*ptlen`, i.e. the bytes written so far, not the whole caller capacity. This matches the authority; it means a caller that reuses the buffer must not assume the unwritten region was touched. |
| R1.6 | `hpke_aead_enc` failure (1549–1550) cleanses the caller's `ct` for `*ctlen` (partial ciphertext). The stack `tag` (1434) is not cleansed; it is the public authentication tag. |
| R1.7 | `hpke_labeled_extract` cleanses `labeled_ikm` before `Drop` (786). `hpke_labeled_expand` does not cleanse `labeled_info` (878–888); its contents are labels, suite id and the public key-schedule context, so this is acceptable only while that classification holds. |

### R4 — Partial initialisation and failure cleanup

| # | Residual obligation, with the concrete site |
|---|---|
| R4.1 | `hpke_do_middle`'s once-only gate is `exportersec != NULL` (2033). On a failure after `nonce` (2185–2190) or `key` (2216–2221) was installed but before `exportersec` (2248–2253), the context is left partially keyed and is **not poisoned**. | R4.2 | `hpke_encap` failure after the shared secret was installed cleanses the allocated extent and NULLs the member (1836–1845), so the KEM cannot be retried (`shared_secret != NULL` is the once-only gate; the failure path NULLs it, so it *can* be retried). This is a deliberate deviation from the authority's plain free; it is recorded in §7. |
| R4.3 | `hpke_decap` failure cleanses `alloc_len` and NULLs `shared_secret`, allowing a retry. On success the length mismatch of R1.3 remains. |
| R4.4 | `OSSL_HPKE_CTX_new` drops the owner on every refusal (2320–2359), and `propq`/`aead_ciph` are installed only after success. The `into_raw` handoff is the only path that transfers ownership. |
